## What Dark Zenith will be (per DESIGN.md)

An Elixir/Phoenix application that serves a fully-functional RPM (dnf) package repository:

- Phoenix renders all web pages (LiveView) and repository metadata (`repomd.xml`, `primary.xml.gz`, etc.).
- RPM files themselves live in Backblaze B2; clients are 302-redirected to time-limited signed URLs (default 30 min). The app server never streams RPM bytes.
- Three top-level surfaces share one core domain: **Web UI (LiveView)**, **REST API (JSON)**, and the **RPM repo endpoint** consumed by `dnf` at `/repos/:slug/...`.

## Architectural decisions worth knowing before editing the spec

These come up repeatedly in DESIGN.md and tend to constrain new changes:

- **Pure-Elixir RPM header parser** for metadata extraction. The system `rpm`/`rpmsign`/`gpg` tools are only used for signing, not parsing.
- **Metadata is generated by an Oban job, never inline.** Repo endpoints serve from a `metadata_revision`/`source_revision` cache and return `503 metadata_not_ready` (with `Retry-After: 5`) when the cache is behind. Repository creation seeds an empty cache row in the same transaction so new empty repos serve valid metadata immediately.
- **Token storage**: secrets (API keys, session tokens, preview tokens, invitations) are stored as `HMAC-SHA-256(SECRET_KEY_BASE, full_token_string)` in lowercase hex. Plaintext is shown to the user exactly once.
- **B2 storage keys** are deterministic and sanitized; `name`/`version`/`release`/`arch` must match `^[A-Za-z0-9._+~-]+$` and `epoch` must be a non-negative integer.
- **Repository deletion** is a hard delete in one DB transaction; B2 object cleanup is a separate idempotent Oban job with up to 20 retries. Same retry/visibility policy applies to metadata regen and email delivery.
- **Bootstrap admin** via `ADMIN_EMAIL` / `ADMIN_PASSWORD` env vars on first boot only (since `REGISTRATION_ENABLED` defaults to `false`).

When proposing a change that touches any of these areas, check DESIGN.md first — the spec is detailed and frequently has an explicit rule for the case you're considering.
